# 审查、返修与交接

## 一、编剧自检不是独立终审

写作者可以检查明显问题并继续改稿，但不得因为自己完成了修改就宣布质量通过。外层编排仍负责用户确认；项目若有独立审稿技能，应由未参与当前版本写作的审稿者给出结论。

## 二、问题分层

发现问题时先定位根因层级：

```text
句子措辞
→ 对话策略与人物声音
→ 场景议程与转向
→ 单集节拍与退出状态
→ 人物驱动力或世界规则
→ 已通过的全剧概要与 Brief
```

不要用一句解释台词修补上游缺失。至少向前追踪到能够解释问题的最早层级，再决定：在本技能内修复，还是返回 `UPSTREAM_CHANGE_REQUEST`。

常见根因：

- 选择显得突兀：缺少压力测试、过渡行动或关系后果；
- 反转随机：必要铺垫在早期场景不存在或被删；
- 对白塞满解释：本应更早通过行动、证据或现场任务建立的信息没有被戏剧化；
- 场景很平：错误人物承担了戏剧功能，或双方没有互相冲突的议程；
- 中段拖慢：连续场景完成同一种功能，只是程度更响；
- 角色失真：当前选择没有被既定目标、关系或底线支撑；
- 结尾只有钩子：本集承诺尚未产生局部结果。

## 三、反模板检查

“像 AI”必须落到文本证据，不使用空泛评分。检查至少两个位置后再判断是否存在：

- 因果重复：每轮都靠巧合、陌生人答案、对手自曝或突然证据；
- 策略重复：所有人物都只会质问、否认和提高音量；
- 表达过度工整：每句同长度、每拍同一种微表情、每场都用完整金句收口；
- 信息密度均匀：每拍同样重，没有铺垫、砸落和余波的疏密；
- 代价即时结清：本集造成的损失全部当集消失，跨集没有未结清后果；
- 人物声音表面化：只靠口头禅，换掉词后人物策略仍完全相同。

类型惯例、仪式重复、喜剧 running gag、人物创伤动作和创作者锁定的固定结构本身不是错误；只有重复损害当前故事时才返修。

## 四、用户返修

接收用户意见后：

1. 标出涉及的场景、台词、人物、事实和时间段；
2. 判断是否影响上游契约、相邻场景、下一集交接或下游已制作素材；
3. 先修改剧本真源；
4. 重新执行相应的场景、对白和因果检查；
5. 重建整份时间轴，不只手改受影响行；
6. 重跑映射和时长校验；
7. 向外层编排提供修改摘要和下游影响，不自行确认通过。

## 五、生产变更请求

先区分：

- `DIRECTORIAL_SOLUTION`：剧情和台词不变，可由拆段、调度、运镜、景别、反应镜头或声音解决；返回导演处理。
- `EQUIVALENT_REALIZATION`：同一人物、选择、代价、信息边界和退出状态可以用更可生产的动作/道具实现；修改剧本候选并重新走用户确认。
- `SCRIPT_REWRITE`：必须改变准确台词、人物选择、因果、关系结果或跨集交接；退回剧本阶段并让外层编排把相关下游状态设为待更新。
- `UPSTREAM_CHANGE_REQUEST`：要求改变已通过的 Brief、全剧概要、角色身份、世界规则或结局承诺；停止本技能修改并交还外层编排。

导演“难拍”不自动等于剧本必须改。先说明导演为何不能在不改含义的前提下解决，再进入后两类。

## 六、交给美术与导演的剧作事实

剧本与时间轴获批后，下游应能读取：

- 每场戏剧功能和准确进入/退出状态；
- 人物表层目标、隐藏目标、策略变化和权力起止；
- 不可替换的证据、道具文字、伤势、服装状态和空间事实；
- 关键情绪的触发、可见反应、人物行动、对方反应和结果；
- 旁白、画外声、画面文字、关键音效及发生时间；
- 准确台词、说话者、顺序、时间槽和必要动作停顿。

剧本说明“为什么必须被看见或听见”，导演决定“怎么拍”。下游若发现 `SOURCE_CONFLICT`，不要猜测或静默改写，返回外层编排处理。
